# サッカー分析AI - 実データ連携用プロキシサーバー

「世界一分かりやすいサッカー分析AI」の `index.html` を、有料の実データAPI(API-Football)に
安全に接続するための、最小限のバックエンドです。

## なぜバックエンドが必要か

これまでの `index.html` は単一ファイルだけで完結していました。しかしAPI-FootballのAPI
キーをHTML/JSに直接書いてしまうと、ページのソースコードを見れば誰でもキーを盗み見・
悪用できてしまいます。このサーバーはキーを `.env`(サーバー側のみ、ブラウザには一切
送られません)に保持し、フロントエンドからは `/api/...` という自前のエンドポイントだけを
呼ばせることで、キーを外部に晒さずに実データを取得できるようにします。

## セットアップ手順

### 1. API-FootballのAPIキーを取得する

1. https://dashboard.api-football.com/register で無料アカウントを作成
2. ログイン後のダッシュボード「My Access」にAPIキーが表示されます
3. まずは無料プラン(100リクエスト/日)で動作確認し、実運用する場合は
   Pro($19/月・7,500リクエスト/日)以上への切り替えを推奨します
   (料金・上限は変わる可能性があるため、契約前に公式サイトで最新情報をご確認ください)

RapidAPI経由でキーを取得した場合は、`.env` の `API_FOOTBALL_VIA_RAPIDAPI` を `true` に
してください(認証ヘッダーの形式が変わります)。

### 2. 起動する(npm installは不要です)

このサーバーは外部パッケージを一切使わず、Node.js標準機能だけで書かれています。
Node.js(18以上)さえパソコンに入っていれば、`npm install` なしでそのまま起動できます。

```bash
cd server
cp .env.example .env
# .env を開いて API_FOOTBALL_KEY にキーを貼り付ける(RapidAPI経由で取得した場合は
# API_FOOTBALL_VIA_RAPIDAPI=true にする)
node server.js
```

Node.jsが入っているか確認したい場合は `node -v` を実行してください。18以上の
バージョン番号(例: v20.11.0)が表示されればOKです。入っていない場合は
https://nodejs.org/ からインストールしてください。

起動後、ブラウザで `http://localhost:8787/` を開いてください。`index.html` もこの
サーバーが自動的に配信するので、これまで通り1つのURLで動作します。
(直接 `index.html` をダブルクリックして開いた場合は `/api/...` に届かずシミュレーション
表示のままになるので、必ず `http://localhost:8787/` の方を開いてください。)

### 3. 動作確認

- `http://localhost:8787/api/health` にアクセスし、`"hasKey": true` になっていればキー設定はOK
- 選手プロフィール画面の「📈 コンディション・パフォーマンス推移」に、実データが取得できた
  選手は「🟢 実データ(API-Football)」というバッジ付きのセクションが追加表示されます
  (取得できなかった選手は、これまで通りAIシミュレーション表示のみになります)
- 「⚽ 試合分析AI」タブに、本日の実際の試合がAPI経由で見つかった場合は
  「📡 本日の実際の試合」という一覧が追加表示されます

## 正直にお伝えしておきたいこと

- このサーバーのコードはAPI-Football公式ドキュメントの仕様通りに実装し、実際にサーバーを
  起動してHTTPリクエストを送る形のテストと、API-Football側のレスポンス形式を模した
  疑似データでの動作確認は行っています。ただし実際のAPIキーを使ったエンドツーエンドの
  動作確認はできていません(このコードを作成した開発環境からは `api-football.com` への
  外部通信がそもそもブロックされているためです)。キーを設定して実際に動かした際、
  レスポンス形式の細部で調整が必要になる可能性があります。実際に本番で1件、
  「`search`だけでは呼び出せず`league`か`team`が必須」というAPI-Football側の制約に
  引っかかったことがあり、その分は`SEARCH_LEAGUES`(下記)を使った修正を反映済みです。
- 選手検索は`SEARCH_LEAGUES`(既定: 主要5リーグ + MLS + サウジ・プロリーグの推測ID)に
  含まれるリーグを順番に試します。登録した選手が見つからない場合、その選手の所属リーグの
  IDが`SEARCH_LEAGUES`に入っていない可能性があるので、`.env`に追加してください
  (API-FootballのAPIリファレンスの「Leagues」エンドポイントでリーグIDを調べられます)。
- 「選手ごとの直近5試合」単位の実データ取得は、API-Football側で複数リクエストの
  組み合わせが必要になりクォータ消費が大きいため、まずは軽量な「今シーズンの
  集計値(出場数・ゴール・アシスト・平均レーティング)」から実装しています。
  「直近5試合ごとの個別レーティング」まで実データ化したい場合は追加実装が必要です
  (`/fixtures?team=...&last=5` → 各試合の `/fixtures/players?fixture=...` を組み合わせる
  方式になり、選手1人あたり最大6リクエスト程度を消費します)。
- キャッシュはサーバーのメモリ上に保持しているだけなので、サーバーを再起動すると
  消えます。アクセスが増えてきた場合はRedisやファイルキャッシュへの置き換えを
  検討してください。
- 常時インターネットに公開する場合は、Vercel・Render・Railwayなどの安価なホスティング
  (月数百円〜)にこのサーバーをデプロイしてください。ローカルで動かしている間だけ
  ではなく、常時起動しておく必要があります。
- `/api/*` には簡易的なレート制限(IPごと1分30リクエストまで)を入れていますが、
  厳密な認証ではありません。不特定多数に公開する場合は追加の対策を検討してください。

## エンドポイント一覧

| エンドポイント | 説明 |
|---|---|
| `GET /api/health` | サーバー稼働確認・キー設定状況の確認 |
| `GET /api/player-season-stats?name=選手名&team=クラブ名` | 選手の今シーズン実データ(出場数・ゴール・アシスト・平均レーティング) |
| `GET /api/fixtures/today?leagues=39,140,78` | 指定リーグの本日の実際の試合一覧 |
